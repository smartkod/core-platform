## 1. `docs/ARCHITECTURE.md`

```markdown
# ARCHITECTURE — Constitution (Anayasa)

> Status: FROZEN
> Bu dosya AI tarafından okunur ama **değiştirilemez**.
> Her değişiklik = yeni ADR + insan onayı.

---

## 1. Stack

- Frontend: Next.js (App Router), React, TypeScript (strict)
- Database: PostgreSQL
- ORM: **Prisma** (tek ORM; Drizzle/Supabase yok)
- Auth: Auth.js
- Validation: Zod
- Payments: Stripe (Checkout + Webhooks)
- Styling: Tailwind CSS
- Testing: Vitest (unit), Playwright (e2e)
- Lint/Format: ESLint + Prettier
- Container: Docker (local PostgreSQL)
- CI: GitHub Actions

---

## 2. Rules (numbered, testable)

1. TypeScript `strict: true`. `any` yasak (istisna: ADR gerekir).
2. `"use client"` sadece gerektiğinde; gerekçe commit mesajında belirtilir.
3. Secret key asla client bundle'a girmez (`NEXT_PUBLIC_` ile başlamaz).
4. Stripe işlemleri yalnızca server tarafında (Server Action / Route Handler).
5. Stripe webhook = billing için **authoritative source**.
6. DB şeması yalnızca Prisma migration ile değişir.
7. Bir feature, başka feature'ın internal implementation'ına doğrudan erişmez.
8. Business logic UI component içine yazılmaz.
9. Aynı business logic iki yerde kopyalanmaz (DRY).
10. Yeni dependency = gerekçe + ADR.
11. Breaking change = DECISIONS.md kaydı.
12. Tüm dış girdi (form, route param, webhook payload) Zod ile validate edilir.
13. Server Action / Route Handler dışında DB erişimi yok.
14. `NEXT_PUBLIC_` dışındaki env değişkenleri yalnızca server'da okunur.
15. Her PR: typecheck + lint + test geçmeli.

---

## 3. Folder Structure

```
src/
├── app/           → Next.js routing only (thin)
├── components/    → shared UI (generic)
├── features/      → feature areas (auth, users, billing, subscriptions, dashboard)
├── lib/           → shared utilities (db client, env, logger)
├── server/        → server-only utilities (auth helpers, stripe client)
└── types/         → shared types
```

### Feature iç yapısı (zorunlu)

```
src/features/<name>/
├── components/    → feature-specific UI
├── actions/       → Server Actions
├── queries/       → read-only DB queries
├── schemas/       → Zod schemas
├── domain/        → pure business logic (test edilebilir)
├── stripe/        → (yalnızca billing/subscriptions)
├── webhooks/      → (yalnızca billing/subscriptions)
└── types.ts
```

---

## 4. Forbidden Patterns

- `any` (istisna: ADR)
- Client'tan gelen `userId` / `price` / `subscriptionStatus`'a güvenmek
- Stripe webhook'u signature doğrulamadan işlemek
- Feature'lar arası doğrudan internal import
- `prisma.$queryRaw` içine string interpolasyon
- `console.log` production kodda (logger kullan)
- `process.env.X` (env modülü kullan)
- UI component içinde DB/Stripe çağrısı

---

## 5. Amendment Process

1. ADR taslağı yaz (`DECISIONS.md`, status: Proposed)
2. İnsan onayı al
3. `ARCHITECTURE.md` güncelle (status: Accepted olunca)
4. PR'da ADR ID referansı ver
```

## 3. `docs/DATABASE.md`

```markdown
# DATABASE

> ORM: **Prisma**. Tek ORM. Drizzle/Supabase yok.

---

## 1. Bağlantı

- Local: Docker PostgreSQL (`docker-compose.yml`)
- Prod: managed PostgreSQL (Neon / RDS / kendi)
- Client: `src/lib/db.ts` (singleton PrismaClient)

## 2. Modeller (özet)

### User
- `id`, `email` (unique), `name`, `createdAt`
- `stripeCustomerId` (unique, nullable)

### Subscription
- `id`, `userId` (FK), `stripeSubscriptionId` (unique)
- `status` (Stripe status mirror)
- `currentPeriodEnd`, `cancelAtPeriodEnd`
- `createdAt`, `updatedAt`

### SubscriptionItem
- `id`, `subscriptionId` (FK)
- `stripePriceId`, `quantity`

### Payment
- `id`, `userId` (FK), `stripePaymentIntentId` (unique)
- `amount`, `currency`, `status`

### Invoice
- `id`, `userId` (FK), `stripeInvoiceId` (unique)
- `amountDue`, `amountPaid`, `status`, `hostedUrl`

### Product / Price
- Stripe tarafında **source of truth**
- Local'de sadece gerekli mapping (`stripePriceId`, `planKey`)

---

## 4. Stripe ↔ Local Mapping

```
users.stripe_customer_id              ← Stripe Customer
subscriptions.stripe_subscription_id  ← Stripe Subscription
subscription_items.stripe_price_id    ← Stripe Price
payments.stripe_payment_intent_id     ← Stripe PaymentIntent
invoices.stripe_invoice_id            ← Stripe Invoice
```

---

## 5. Rules

1. Her Stripe ID için `@unique` index.
2. Migration olmadan şema değişmez (`prisma migrate dev`).
3. `prisma db push` production'da yasak.
4. Stripe verisini körü körüne kopyalama; sadece uygulamanın
   ihtiyacı olan local state tutulur.
5. Soft delete yok (Stripe tarih tutar; gerekirse `deletedAt` ADR ile).
6. Tüm ilişkiler explicit (`onDelete` davranışı belirtilir).
7. Para birimi `Int` (kuruş) olarak tutulur, `Float` yasak.
```

## 4. `docs/API.md`

```markdown
# API

> İletişim: **Server Actions** (öncelikli) + Route Handlers (webhook, public API).

---

## 1. Server Actions

- Konum: `src/features/<name>/actions/`
- Her action:
  1. Zod ile input validate
  2. Auth kontrolü (server-side)
  3. Authorization (kaynak sahibi mi?)
  4. Business logic (`domain/` çağrısı)
  5. DB erişimi (`queries/` veya `domain/`)
  6. `revalidatePath` / `revalidateTag`
  7. Typed result döner (`{ ok: true, data }` | `{ ok: false, error }`)

### Action şablonu

```ts
"use server";
import { z } from "zod";
import { auth } from "@/server/auth";
import { db } from "@/lib/db";

const Input = z.object({ /* ... */ });

export async function doSomething(raw: unknown) {
  const session = await auth();
  if (!session?.user) return { ok: false, error: "UNAUTHORIZED" };

  const parsed = Input.safeParse(raw);
  if (!parsed.success) return { ok: false, error: "INVALID_INPUT" };

  // ... business logic
  return { ok: true, data: null };
}
```

---

## 2. Route Handlers

- Konum: `src/app/api/<path>/route.ts`
- Kullanım: webhook, public API, file upload
- Her handler: input validate + auth (gerekliyse) + idempotency

### Webhook şablonu

```ts
export async function POST(req: Request) {
  const raw = await req.text();
  const sig = req.headers.get("stripe-signature");
  // 1. verify signature
  // 2. idempotency (event.id)
  // 3. transaction
  // 4. update local state
  return new Response(null, { status: 200 });
}
```

---

## 3. Response Sözleşmesi

```ts
type ActionResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: string; details?: unknown };
```

- Hata mesajları **kullanıcıya gösterilebilir** olmalı.
- Stack trace client'a gönderilmez.
- `error` kodu makine-okunur (`UNAUTHORIZED`, `INVALID_INPUT`, ...).

---

## 4. Versioning

- Server Action imzası değişirse: **breaking change** → ADR.
- Public API (`/api/*`) değişirse: ADR + deprecation notu.
```

## 5. `docs/SECURITY.md`

```markdown
# SECURITY

> AI için sınır listesi. İhlal = PR reddi.

---

## NEVER

- expose `DATABASE_URL`, Stripe secret, auth secrets
- trust client-supplied `userId`, `price`, `subscriptionStatus`, `role`
- process Stripe webhook without signature verification
- bypass authorization checks
- disable CSRF without ADR
- log secrets / PII / full request bodies
- `NEXT_PUBLIC_` ön eki ile secret yayınlamak
- `prisma.$queryRaw` içine string interpolasyon
- client'ta `process.env.SECRET` okumak

---

## ALWAYS

- validate input with Zod at boundary (Server Action / Route Handler)
- authorize server-side (never trust client)
- use Prisma parameterized queries
- verify webhook signatures (`stripe.webhooks.constructEvent`)
- validate env vars at boot (`src/lib/env.ts`)
- log security-sensitive failures with context (logger)
- use `httpOnly`, `secure`, `sameSite` cookies
- rate-limit public endpoints (gerekirse ADR)

---

## Env Validation

`src/lib/env.ts`:

```ts
import { z } from "zod";

const ServerEnv = z.object({
  DATABASE_URL: z.string().url(),
  STRIPE_SECRET_KEY: z.string().startsWith("sk_"),
  STRIPE_WEBHOOK_SECRET: z.string().startsWith("whsec_"),
  AUTH_SECRET: z.string().min(32),
});

export const env = ServerEnv.parse(process.env);
```

- Boot'ta fail → uygulama başlamaz.
- Client env ayrı: `NEXT_PUBLIC_*` (sadece public).

---

## Authorization Matrix

| Kaynak              | Kim erişir                     |
|---------------------|--------------------------------|
| `User` (kendi)      | session.user.id === user.id    |
| `Subscription`      | sahibi                         |
| `Invoice`           | sahibi                         |
| Admin alanları      | `role === "ADMIN"` (server)    |
| Webhook             | Stripe signature               |
```

## 6. `docs/BILLING.md`

```markdown
# BILLING

> Stripe entegrasyonu. Genel `ARCHITECTURE.md`'ye gömülmez.

---

## 1. Source of Truth

### Stripe
- payment status
- subscription status
- invoices
- payment events

### Application DB
- user ↔ customer link
- access state (entitlement)
- internal billing state
- audit için minimal mirror

**Kural:** Stripe verisini körü körüne kopyalama. Sadece uygulamanın
ihtiyacı olan local state tutulur.

---

## 2. Webhook Pipeline (zorunlu sıra)

```
1. verify signature (stripe.webhooks.constructEvent)
2. idempotency check (event.id)
3. DB transaction başlat
4. local state güncelle
5. transaction commit
6. 200 dön
```

- Herhangi bir adım başarısız → 4xx/5xx dön (Stripe retry eder).
- İdempotency tablosu: `WebhookEvent (id, type, processedAt)`.

---

## 3. Checkout Akışı

```
1. Client → Server Action (planKey)
2. Server: planKey → stripePriceId (server-side mapping)
3. Server: Stripe Checkout Session oluştur
4. Client → Stripe Checkout'a yönlendir
5. Stripe → webhook (checkout.session.completed)
6. Server: local Subscription kaydı oluştur
```

**Kural:** Client'tan gelen `price` / `priceId` **asla** doğrudan
Stripe'a gönderilmez. Server-side mapping zorunlu.

---

## 4. Subscription State Machine

```
incomplete → active → past_due → canceled
                  ↘ trialing ↗
```

- Geçişler yalnızca **webhook** ile tetiklenir.
- Client'tan gelen durum bilgisi yok sayılır.

---

## 5. Forbidden

- Webhook'suz subscription state güncellemek
- Client'tan gelen price/plan bilgisine güvenmek
- Stripe secret'ı client'a sızdırmak
- Webhook signature doğrulamadan işlemek
- Idempotency olmadan webhook işlemek
- Stripe verisini DB'ye gereksiz kopyalamak

---

## 6. Test

- Stripe CLI ile local webhook test (`stripe listen --forward-to`).
- Test mode key'leri (`sk_test_`, `whsec_test_`) kullanılır.
- Production key'leri asla local'de.
```

## 7. `docs/DECISIONS.md`

```markdown
# DECISIONS — ADR Index

> Her mimari karar burada. AI yeni karar verecekse önce burayı okur.

---

## Index

| ID      | Decision                          | Status   | Risk     | Date       |
|---------|-----------------------------------|----------|----------|------------|
| ADR-001 | PostgreSQL                        | Accepted | HIGH     | 2025-01-15 |
| ADR-002 | Prisma (Drizzle/Supabase değil)   | Accepted | MEDIUM   | 2025-01-15 |
| ADR-003 | Stripe Checkout                   | Accepted | HIGH     | 2025-01-15 |
| ADR-004 | Server Actions over Route Handlers| Accepted | MEDIUM   | 2025-01-15 |
| ADR-005 | Auth.js                           | Accepted | HIGH     | 2025-01-15 |
| ADR-006 | Feature-based folder structure    | Accepted | LOW      | 2025-01-15 |
| ADR-007 | "Domain" yerine "Feature Area"    | Accepted | LOW      | 2025-01-15 |
| ADR-008 | Zod ile env validation            | Accepted | MEDIUM   | 2025-01-15 |

---

## ADR-001: PostgreSQL

### Status
Accepted

### Context
Uygulama ilişkisel veri (User, Subscription, Invoice, Payment) tutuyor.
Transaction ve join gerekiyor.

### Decision
PostgreSQL kullanılacak.

### Alternatives Rejected
- MongoDB — relational integrity yok
- SQLite — concurrent write scale yok

### Consequences
+ ACID, olgun ekosistem, Prisma uyumu
- Ops yükü (Docker local, managed prod)

---

## ADR-002: Prisma (Drizzle/Supabase değil)

### Status
Accepted

### Context
PostgreSQL için ORM gerekli. "Data proje içinde olsun" tercihi var.

### Decision
**Prisma** kullanılacak. Drizzle ve Supabase **kullanılmayacak**.

### Alternatives Rejected
- **Drizzle** — SQL-like kontrol güzel ama migration yönetimi daha
  manuel; mevcut ihtiyaç için Prisma yeterli.
- **Supabase** — ORM değil, platform. Auth/realtime/storage
  ihtiyacı yok; gereksiz bağımlılık.

### Consequences
+ Otomatik migration, geniş ekosistem, AI uyumu
+ Tek ORM, tek source of truth
- Edge runtime sınırlı (şimdilik sorun değil)

### Forbidden
- AI "Drizzle kullanalım" derse → bu ADR'ye bak, reddet.
- AI "Supabase ekleyelim" derse → bu ADR'ye bak, reddet.

---

## ADR-003: Stripe Checkout

### Status
Accepted

### Context
Ödeme altyapısı gerekli. PCI scope minimum olmalı.

### Decision
Stripe **Checkout** kullanılacak (hosted).

### Alternatives Rejected
- Custom card form — PCI scope, gereksiz sorumluluk
- Stripe Elements — Checkout yeterli, ekstra UI yükü

### Consequences
+ PCI scope minimum
+ Hızlı entegrasyon
- UI Stripe kontrolünde

---

## ADR-004: Server Actions over Route Handlers

### Status
Accepted

### Context
Client-server iletişimi için iki yol var.

### Decision
Öncelikli: **Server Actions**. Route Handlers yalnızca webhook,
public API, file upload için.

### Consequences
+ Tip güvenli, az boilerplate
+ Progressive enhancement
- Public API için uygun değil (Route Handler kullan)

---

## ADR-005: Auth.js

### Status
Accepted

### Context
Auth çözümü gerekli. Supabase auth kullanılmıyor (ADR-002).

### Decision
**Auth.js** (NextAuth v5) kullanılacak.

### Alternatives Rejected
- Supabase Auth — ADR-002 ile çelişir
- Clerk — vendor lock-in, ekstra maliyet
- Kendi auth — güvenlik riski

### Consequences
+ Next.js ile native
+ Esnek provider desteği
- v5 beta (dikkatli takip)

---

## ADR-006: Feature-based Folder Structure

### Status
Accepted

### Context
Klasik `components/hooks/services/utils` yapısı AI ile ölçeklenmiyor.

### Decision
`src/features/<name>/` merkezli yapı. Her feature kendi
`components/ actions/ queries/ schemas/ domain/ types.ts` içerir.

### Consequences
+ AI bütün projeyi dolaşmaz
+ Feature sınırları net
- Shared kod için `src/lib/`, `src/components/` disiplini gerekir

---

## ADR-007: "Domain" yerine "Feature Area"

### Status
Accepted

### Context
"Domain" kelimesi DDD ve DNS ile karışıyor.

### Decision
İş alanı = **Feature Area**. DNS = **Hostname**.

### Consequences
+ Karışıklık yok
+ AI için net
- DDD terminolojisinden sapma (kabul edilebilir)

---

## ADR-008: Zod ile env validation

### Status
Accepted

### Context
Env değişkenleri runtime'da fail edebilir.

### Decision
`src/lib/env.ts` boot'ta Zod ile validate eder. Fail → uygulama başlamaz.

### Consequences
+ Erken hata
+ Tip güvenli env
- Boot'a küçük maliyet

## 8. `docs/CONTRACT.md`

```markdown
# AI DEVELOPMENT CONTRACT

> Her AI görevi bu sözleşmeye uyar. İhlal = PR reddi.

---

## Before Coding

1. Read `ARCHITECTURE.md`
2. Read relevant feature docs (`FEATURES.md`, `DATABASE.md`, `BILLING.md`, `SECURITY.md`)
3. Read `DECISIONS.md` — mevcut kararlarla çelişki var mı?
4. Identify affected feature areas (`src/features/*`)
5. Search existing implementation — duplicate yaratma
6. Produce **IMPACT ANALYSIS** + **CHANGE PLAN**
7. Determine **RISK LEVEL** (LOW / MEDIUM / HIGH / CRITICAL)
8. If HIGH/CRITICAL → wait for human approval

---

## During Coding

9. Follow existing architecture (no new patterns without ADR)
10. Keep changes minimal — sadece ilgili dosyalar
11. No new dependency without justification + ADR
12. No silent schema change — Prisma migration required
13. No modification of unrelated files
14. Every external input validated with Zod
15. No `any` (istisna: ADR)
16. No business logic in UI components
17. No cross-feature internal imports

---

## After Coding

18. Run: `pnpm typecheck && pnpm lint && pnpm test`
19. Validate affected flows manually if needed
20. Report:
    - changed files
    - architectural impact
    - new ADRs needed
    - unresolved risks
21. If architectural violation detected → **stop, report, do not merge**

---

## Reporting Format

```yaml
task: "<kısa açıklama>"
risk: LOW | MEDIUM | HIGH | CRITICAL
affected_features: [auth, billing]
changed_files:
  - src/features/...
new_adrs: []
architectural_impact: "none | minor | major"
tests_run: [typecheck, lint, unit, e2e]
unresolved_risks: []
```

| Durum                              | Aksiyon                    |
|------------------------------------|----------------------------|

| DB migration (additive)            | HIGH → insan onayı         |
| DB migration (destructive)         | CRITICAL → insan + ADR     |
| Stripe değişikliği                 | HIGH → insan onayı         |
| Auth değişikliği                   | HIGH → insan onayı         |
| Security.md NEVER ihlali           | DUR, asla                   |
| ADR ile çelişki                    | DUR, insan onayı           |

## 9. `docs/WORKFLOW.md`

```markdown
# WORKFLOW — Risk-Based Agent Workflow

> Pipeline: ARCHITECT → CODER → TESTER → ARCHITECT VALIDATE

---

## 1. Pipeline

```
USER REQUEST
     ↓
ARCHITECT
  ├── ANALYZE   → impact
  ├── PLAN      → change plan
  └── RISK      → LOW / MEDIUM / HIGH / CRITICAL
     ↓
   ┌─────────────────────────────┐
   │ LOW       → CODER otomatik  │
   │ MEDIUM    → CODER + test    │
   │ HIGH      → human approval  │
   │ CRITICAL  → human + ADR     │
   └─────────────────────────────┘
     ↓
CODER
     ↓
TESTER (typecheck, lint, unit, e2e)
     ↓
ARCHITECT VALIDATE (constitution check)
     ↓
   ┌─────────────────────────────┐
   │ Violation?                  │
   │ Evet → rollback + report    │
   │ Hayır → DONE                │
   └─────────────────────────────┘
```

---

## 2. Risk Table

| Değişiklik                          | Risk     | Approval          |
|-------------------------------------|----------|-------------------|
| UI metni / copy                     | LOW      | otomatik          |
| Yeni component (mevcut pattern)     | LOW      | otomatik          |
| Bug fix (lokal)                     | LOW      | otomatik          |
| Yeni feature (mevcut feature area)  | MEDIUM   | plan review       |
| Yeni feature area                   | MEDIUM   | plan review       |
| Yeni dependency                     | MEDIUM   | ADR + review      |
| DB migration (additive)             | HIGH     | human approval    |
| Auth değişikliği                    | HIGH     | human approval    |
| Stripe billing değişikliği          | HIGH     | human approval    |
| Webhook pipeline değişikliği        | HIGH     | human approval    |
| DB schema redesign                  | CRITICAL | human + ADR       |
| Payment/security architecture       | CRITICAL | human + ADR       |
| ADR ile çelişen değişiklik          | CRITICAL | human + ADR       |

## 5. Human Approval Gate

Şu durumlarda **zorunlu** insan onayı:

- Risk = HIGH veya CRITICAL
- Yeni dependency
- DB migration (additive veya destructive)
- Auth / Stripe / Security değişikliği
- ADR ile çelişki
- `ARCHITECTURE.md` / `SECURITY.md` değişikliği

Onay formatı:

approved_by: <isim>
adr: ADR-XXX

## 15. `prisma/schema.prisma` (başlangıç)

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id               String   @id @default(cuid())
  email            String   @unique
  name             String?
  stripeCustomerId String?  @unique
  createdAt        DateTime @default(now())

  subscriptions    Subscription[]
  payments         Payment[]
  invoices         Invoice[]
}

model Subscription {
  id                   String   @id @default(cuid())
  userId               String
  stripeSubscriptionId String   @unique
  status               String
  currentPeriodEnd     DateTime?
  cancelAtPeriodEnd    Boolean  @default(false)
  createdAt            DateTime @default(now())
  updatedAt            DateTime @updatedAt

  user                 User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  items                SubscriptionItem[]

  @@index([userId])
}

model SubscriptionItem {
  id               String @id @default(cuid())
  subscriptionId   String
  stripePriceId    String
  quantity         Int    @default(1)

  subscription     Subscription @relation(fields: [subscriptionId], references: [id], onDelete: Cascade)

  @@index([subscriptionId])
}

model Payment {
  id                    String   @id @default(cuid())
  userId                String
  stripePaymentIntentId String   @unique
  amount                Int
  currency              String
  status                String
  createdAt             DateTime @default(now())

  user                  User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
}

model Invoice {
  id              String   @id @default(cuid())
  userId          String
  stripeInvoiceId String   @unique
  amountDue       Int
  amountPaid      Int
  status          String
  hostedUrl       String?
  createdAt       DateTime @default(now())

  user            User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
}

model WebhookEvent {
  id          String   @id
  type        String
  processedAt DateTime @default(now())
}
```
