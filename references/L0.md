> **Kapsam kuralı:** Bu belge yalnızca **kendi** gereksinimlerini yazar.

> `User`, `Wallet`, `Token`, `File`, `AI` gibi kavramlar L0'da **geçmez**.

---

## 1. Bu seviye ne ekler

`corectl new <app> --level=L0` çalıştırıldığında üretilen her şey ve onu taşıyan kernel.

Bir uygulama L0 ile:

- ayağa kalkar, `/healthz`, `/readyz`, `/version` yanıtlar,
- config'i doğrular ve üretimde eksik sırla **başlamaz**,
- PostgreSQL'e bağlanır, migration'ları uygular,
- modüllerini bağımlılık sırasına göre başlatır,
- tüm yanıtlarda tek hata zarfı ve `X-Request-ID` döner,
- SIGTERM'de 10 saniye içinde temiz kapanır.

**L0'da hiçbir iş endpoint'i yoktur.** Kimlik yok, cüzdan yok, dosya yok.
Yalnızca altyapı.

## 2. `corectl new --level=L0` çıktısı

### 2.1 Üretilen dizin ağacı

```
<app>/
├── go.mod                       require core-platform vX.Y.Z
├── go.sum
├── .env.example                 tüm değişkenler, sır yok
├── .gitignore
├── Makefile                     run · build · test · lint · fmt · migrate · docker-*
├── Dockerfile                   çok aşamalı, non-root, healthcheck
├── docker-compose.yml           app + postgres, tek port
├── config/
│   ├── config.yaml              varsayılanlar
│   └── modules.yaml             modül durumları (L0'da boş)
├── migrations/
│   └── .gitkeep
├── cmd/server/main.go           30 satırı geçmez
└── internal/
    ├── modules/
    │   └── example/             boş modül örneği (silinebilir)
    │       ├── module.go
    │       ├── service.go
    │       └── service_test.go
    └── platform_test.go         golden path smoke testi
```

### 2.2 `main.go` — 30 satır sınırı

```go
func main() {
    if err := platform.Run(platform.App{
        Name:    "xscope",
        Version: version,
        Modules: []contract.Module{
            example.New(),
        },
    }); err != nil {
        log.Fatal(err)
    }
}
```

`platform.Run` şu sırayı **tek başına** yürütür; `main.go` hiçbir adımı bilmez:

1. Config yükle + doğrula
2. Logger kur
3. DB bağlan (retry + timeout)
4. Migration uygula
5. Modülleri kaydet ve başlat (topolojik sıra)
6. HTTP sunucusunu başlat
7. `SIGINT`/`SIGTERM` bekle → graceful shutdown

## 4. Uygulama Kararları

### 4.1 `platform` paket düzeni

```
platform/
├── config/       yükleme, env override, doğrulama
├── logger/       zap sarmalayıcı, JSON/console
├── database/     bağlantı, retry, pool, health
├── migrate/      SQL runner, advisory lock
├── module/       registry, topolojik sıra, yaşam döngüsü
├── http/         server, router, middleware, hata zarfı
├── health/       liveness, readiness, version
├── security/     CORS, güvenlik başlıkları, rate limit, CSRF
├── i18n/         embed.FS, eksik anahtar fallback
├── clock/        enjekte edilebilir zaman (test edilebilirlik)
└── run.go        Run(App) — 7 adımlı bootstrap
```

`platform` hiçbir `mod/**` paketini import **etmez**.

### 4.2 Modül sözleşmesi

```go
type Module interface {
    Name() string
    Version() string
    Dependencies() []string
    Migrate(ctx context.Context, db *gorm.DB) error
    RegisterRoutes(g *echo.Group, d Dependencies)
    Start(ctx context.Context) error
    Stop(ctx context.Context) error
}
```

- Başlatma sırası: Kahn algoritması, döngü tespiti.
- Bilinmeyen bağımlılık → **fail-closed**, süreç başlamaz.
- `Start` hatası → daha önce başlayanlar **ters sırayla** durdurulur.
- Durumlar: `registered`, `migrated`, `started`, `failed`, `stopped`.

`config/modules.yaml` ile modül durumu:

| Durum | Davranış |
|---|---|
| `ENABLED` | Yüklenir |
| `DISABLED` | Yüklenmez; route yok, migration yok |
| `MAINTENANCE` | Route'lar 503 döner |
| `EXPERIMENTAL` | Yalnızca `APP_ENV != production` |
| `DEPRECATED` | Yüklenir, `Deprecation` başlığı ekler, log uyarısı |

> Bu, **modül** bazında operasyonel bir anahtardır — tak/çıkar mimarisi değil.
> Modül binary'de yoksa bu dosyada `ENABLED` yazmak **fail-fast** üretir (drift tespiti).

### 4.3 Config

- Öncelik: **env > yaml > varsayılan**.
- Tek port kaynağı: `SERVER_PORT` (varsayılan 8080).
- Üretimde fail-fast: `JWT_*_SECRET`, `DB_PASSWORD`, `CORS_ALLOWED_ORIGINS` boşsa başlamaz.
- Üretimde reddedilen: `CORS_ALLOWED_ORIGINS=*`, `DB_SSLMODE=disable`.
- `.env.example` tüm değişkenleri içerir; repoda gerçek sır yok.

| Değişken | Varsayılan |
|---|---|
| `APP_ENV` | `development` |
| `SERVER_HOST` / `SERVER_PORT` | `0.0.0.0` / `8080` |
| `DB_HOST` / `DB_PORT` | `localhost` / `5432` |
| `DB_USER` / `DB_PASSWORD` | `postgres` / — |
| `DB_NAME` | uygulama adı |
| `DB_SSLMODE` | `disable` (üretimde zorunlu `require`) |
| `DB_MAX_OPEN_CONNS` | `25` |
| `CORS_ALLOWED_ORIGINS` | — (üretimde zorunlu) |
| `HTTP_BODY_LIMIT` | `8M` |
| `HTTP_REQUEST_TIMEOUT` | `30s` |
| `HTTP_SHUTDOWN_TIMEOUT` | `10s` |
| `LOG_LEVEL` / `LOG_FORMAT` | `info` / `json` |

### 4.4 HTTP katmanı

**Middleware sırası (sabit):**
```
RequestID → Recover → AccessLog → Timeout → BodyLimit
→ SecurityHeaders → CORS → RateLimit → Auth (grup bazlı) → Handler
```

**Tek hata zarfı:**
```json
{
  "success": false,
  "error": { "code": "VALIDATION_ERROR", "message": "...", "details": [] },
  "request_id": "..."
}
```

**Sentinel → HTTP eşlemesi (tek yerde):**

| Sentinel | Kodu | HTTP |
|---|---|---|
| `ErrUnauthorized` | `UNAUTHORIZED` | 401 |
| `ErrForbidden` | `FORBIDDEN` | 403 |
| `ErrNotFound` | `NOT_FOUND` | 404 |
| `ErrValidation` | `VALIDATION_ERROR` | 422 |
| `ErrConflict` | `CONFLICT` | 409 |
| `ErrRateLimited` | `RATE_LIMITED` | 429 |
| `ErrNotImplemented` | `NOT_IMPLEMENTED` | 501 |
| `ErrProviderFailure` | `PROVIDER_ERROR` | 502 |
| diğer | `INTERNAL` | 500 |

5xx'te iç mesaj client'a **gitmez**, log'a gider.

**Sağlık endpoint'leri:**
- `GET /healthz` → süreç ayakta mı (DB'ye bakmaz)
- `GET /readyz` → DB + kritik bağımlılık; kapalıysa **503**
- `GET /version` → ad, sürüm, commit, derleme zamanı

### 4.5 Migration runner

- Şema başına ayrı `schema_migrations` tablosu.
- Dosya adı sırası = uygulama sırası (`0001_...`).
- Her dosya kendi transaction'ında; hata → rollback.
- Uygulanmış dosyanın hash'i değişmişse **hata** (sessiz atlama yok).
- `pg_advisory_lock(hashtext(schema))` ile eşzamanlı deploy engellenir.
- Üretimde `AutoMigrate` **yasak**.
- Şema adı doğrulanır (`^[a-z_][a-z0-9_]*$`), yoksa oluşturulur.

### 4.6 Gözlemlenebilirlik

- JSON log; `request_id`, `user_id` (varsa), `module`, `duration`.
- `/metrics` Prometheus iskeleti (istek sayısı, süre, hata).
- Yavaş sorgu logu, eşik config'ten (`DB_SLOW_QUERY=200ms`).
- Panic tek middleware'de yakalanır; süreç ayakta kalır.

### 4.7 Zamanlanmış işler

- `platform/clock` enjekte edilebilir; testler gerçek beklemeye girmez.
- Çok instance'ta tek çalışma: `pg_advisory_lock`.

### 4.8 Güvenlik

- CORS açık origin listesi; üretimde `*` reddedilir.
- Güvenlik başlıkları; HSTS yalnızca HTTPS'te.
- Rate limiter: TTL temizlikli in-memory; çok instance için Redis opsiyonu (V1'de yok).
- Body limit ve timeout zorunlu.
- Repoda sır yok; `.env.example` sadece isimler.

### 4.9 Docker

- Çok aşamalı build; çalışma imajında Go yok.
- Non-root kullanıcı.
- `HEALTHCHECK` → `/healthz`.
- `.env.example` imaja **kopyalanmaz**.
- `docker-compose.yml`: app + postgres, kaynak mount yok,
  `depends_on: condition: service_healthy`, tek port.

### 4.10 `corectl` — bu seviyede teslim edilen

| Komut | L0'da |
|---|---|
| `new --level=L0` | Tam |
| `new --level=L0 --only=…` | `--only` L0'da etkisiz (tüm kernel zorunlu) |
| `add module` | Tam |
| `add level L1/L2` | Bu seviye yayınlanmamışsa net hata |
| `upgrade` | Tam (L0 sürüm farkı) |
| `doctor` | Migration + config kontrolü |

## 5. Test Kararları

### 5.1 İyi bir testin tanımı

Dışa dönük davranışı doğrular; iç ayrıntıyı değil. Refactor'da kırılmaz,
davranış değişince kırılır. Testler gerçek PostgreSQL kullanır —
SQLite'a kaçış yok (JSONB, `ILIKE`, advisory lock gerekli).

### 5.2 Zorunlu senaryolar

**Config**

1. env > yaml > varsayılan önceliği doğru.
2. Üretimde `JWT_SECRET` boş → süreç **başlamaz**, net hata.
3. Üretimde `CORS_ALLOWED_ORIGINS=*` → başlamaz.
4. Üretimde `DB_SSLMODE=disable` → başlamaz.
5. Geliştirmede aynı değerler kabul edilir.

**Modül yönetimi**

6. Bağımlılık sırası doğru uygulanır (A→B→C ise C önce başlar).
7. Döngü tespit edilir, süreç başlamaz.
8. Bilinmeyen bağımlılık → fail-closed.
9. `Start` hatasında önceki modüller **ters sırayla** durur.
10. `DISABLED` modülün route'u yok, migration'ı çalışmaz.
11. Binary'de olmayan modül config'te `ENABLED` ise fail-fast.
12. `MAINTENANCE` modülün route'ları 503 döner.

**Migration**

13. Dosya sırası doğru uygulanır.
14. Hatalı migration rollback eder; kısmi uygulama olmaz.
15. Değişmiş dosya hata verir.
16. İki eşzamanlı çalıştırma kilitlenir; biri işler.
17. Uygulama şeması ile çekirdek şeması karışmaz.

**HTTP**

18. Sentinel → durum kodu eşlemesi doğru.
19. 5xx'te iç mesaj sızmaz.
20. Her yanıtta `X-Request-ID` var ve log'da aynı.
21. Body limit aşımı 413.
22. Timeout aşımı 503/504.
23. `/healthz` DB kapalıyken 200, `/readyz` 503.

**Bootstrap**

24. SIGTERM'de devam eden istek tamamlanır, süreç 10 sn içinde kapanır.
25. `main.go` 30 satırı geçmez (statik test).

### 5.3 Araçlar

`testing`, gerçek PostgreSQL (compose profili), `httptest`, `go test -race`.
Coverage eşiği: **%50** (kernel kritik).

## 6. Kabul Kriterleri

L0 tamamdır ancak aşağıdakilerin **tamamı** sağlanırsa.

### 6.1 Derleme ve sınırlar

1. `gofmt -l .` boş.
2. `go build ./...`, `go vet ./...`, `staticcheck ./...`, `govulncheck ./...` hatasız.
3. `go test -race ./...` yeşil; coverage ≥ %50.
4. `platform/**` hiçbir `mod/**` paketini import etmiyor (depguard kanıtı).
5. `contract/**` dışında hiçbir paket uygulama tarafından import edilmiyor
   (depguard kanıtı, uygulama tarafında).
6. L0'da hiçbir domain kavramı yok: `User`, `Wallet`, `Token`, `File`, `AI`
   dizesi `platform/` altında geçmiyor (statik kontrol).
7. Repoda sır yok; `.env.example` tüm değişkenleri içeriyor.

### 6.2 `corectl` ve golden path

8. `corectl new demo --level=L0` üretilen proje **elle düzenleme olmadan**
   `go build ./...` geçer.
9. Aynı proje `docker compose up` ile Postgres + uygulamayı ayağa kaldırır.
10. `/healthz`, `/readyz`, `/version` **200** döner.
11. Ölçüm: komuttan `/readyz` 200'e kadar **30 saniyenin altında**
    (Docker imajları önbellekteyken). Aşarsa bu kriter **başarısız**.
12. Üretilen projede en az 2 test var ve `go test ./...` yeşil.
13. `corectl add module foo` çalışır; üretilen modül derlenir ve route'u yanıt verir.
14. `corectl doctor` eksik config'i ve uygulanmamış migration'ı raporlar.

### 6.3 Davranış

15. Üretim modunda `JWT_SECRET` boşsa süreç hiç başlamaz.
16. Döngüsel bağımlılık bildiren modülle süreç başlamaz.
17. `Start` hatasında önceki modüller ters sırayla durur (log kanıtı).
18. Migration ikinci kez çalıştığında hiçbir şey uygulanmaz.
19. Değiştirilmiş migration dosyası hata verir.
20. `SIGTERM` → devam eden istek tamamlanır, 10 sn içinde kapanır.
21. DB kapalıyken `/healthz` 200, `/readyz` 503.
22. Tüm yanıtlarda `X-Request-ID` var.
23. 5xx yanıtında iç hata mesajı yok.
24. `docker compose up` tek komutla çalışır; imaj non-root kullanıcıyla koşar.

### 6.4 Sürümleme

25. `core-platform` `v0.1.0` etiketli.
26. `demo` uygulaması `go.work` **olmadan** derleniyor.
27. `corectl upgrade` `v0.1.0 → v0.1.1` farkını uyguluyor, uygulama derleniyor.

### 8.3 Bir sonraki adım

`L0.md` kriterleri yeşil olduğunda L1 eklenir: `identity`, `authz`, `files` ve
`notifications`. L2 ise `organization` ve `catalog` ile hizmet katmanını
tamamlar. Seviye içerikleri `cmd/corectl/levels` tablosunda tek yerde tutulur.
