> sağlayıcıları (Stripe, PayTR) **bu sürüme dahil değildir**; sonradan adaptör
> olarak eklenir. Motor, arayüz ve çalışan bir manuel sağlayıcı teslim edilir.
>
> **Onaylanmış kapsam kararı (2026-11-02):** Ekonomi motoruna çekirdek özellikler
> eklendi: (1) ücretsiz üyeliğe hoş geldin jetonu, (2) ödüllü reklam modülü
> (video/resim/metin; geri sayımlı izleme veya tıklama ile jeton; affiliate URL),
> (3) sunucu tarafı günlük/aylık jeton kazanma limitleri, admin tarafından

> kanıtlanır; gerçek sağlayıcı sonraki sürümde adaptör olarak gelir.

## 1. Bu seviye ne ekler

```bash
corectl new fitscope --level=L2
```

L1'in üstüne:

| Modül | Ne getirir |
|---|---|
| `economy` | Cüzdan ledger'ı, ürün kataloğu, sipariş, ödeme adaptör arayüzü, entitlement |
| `economy/ads` | Reklam kataloğu, imzalı izleme oturumu, affiliate tıklama takibi, ödül limitleri |

Şema: `wallet_accounts`, `wallet_entries`, `products`, `orders`, `payments`,
`payment_events`, `entitlements`, `refunds`, `ads`, `ad_view_sessions`,
`ads_clicks`, `reward_settings`.
Arayüz: `contract/economy` → `Wallet`, `Entitlements`, `Payments`, `Ads`.

Bir uygulama L2 ile: kullanıcıya jeton yükleyebilir, harcatabilir, ürün
sattırabilir, premium kilidi açtırabilir, izlediği reklamlarla jeton
kazandırabilir (limitli), jeton/abonelik paketi sattırabilir — hepsi aynı
motorla, sağlayıcıdan bağımsız.

## 3. Uygulama Kararları

### 3.1 Para birimi modeli

- Para birimi bir **koddur**: `TOKEN`, `TRY`, `USD`, `FITCOIN`. `^[A-Z][A-Z0-9]{2,7}$`.
- Geçerli kodlar config'ten: `economy.currencies: [TOKEN, TRY]`. Tanımsız kod reddedilir.
- Ölçek config'te: `TOKEN` → 0, `TRY` → 2. Tüm tutarlar **minor unit** `int64`.
- **`float` hiçbir yerde kullanılmaz.** JSON'da tutarlar `int64`.
- Para birimi dönüşümü **yoktur**; farklı kodu ayrı hesaptır.

### 3.2 Şema

```sql
wallet_accounts(id uuid PK, user_id uuid, currency varchar(8),
                balance_minor bigint CHECK (>=0), UNIQUE(user_id, currency))

wallet_entries(id uuid PK, account_id uuid, delta_minor bigint CHECK (<>0),
               balance_after_minor bigint CHECK (>=0), reason_code varchar(40),
               actor varchar(20), actor_id uuid NULL, ref_type varchar(40) NULL,
               ref_id uuid NULL, idempotency_key varchar(120) NULL, created_at)
  UNIQUE (account_id, idempotency_key) WHERE idempotency_key IS NOT NULL

products(id uuid PK, code UNIQUE, name, kind, currency, amount_minor bigint CHECK(>0),
         interval NULL, grants jsonb, active bool)

orders(id uuid PK, user_id, product_id, amount_minor, currency, provider, status,
       idempotency_key UNIQUE, reference_code UNIQUE, expires_at, timestamps)

payments(id uuid PK, order_id, provider, provider_ref, status, amount_minor,
         currency, paid_at, failure_code, raw_payload jsonb, UNIQUE(provider, provider_ref))

payment_events(id uuid PK, provider, event_id, order_id, type, payload jsonb,
               processed_at, UNIQUE(provider, event_id))

entitlements(id uuid PK, user_id, product_id NULL, code varchar(80), source,
             starts_at, ends_at NULL, revoked_at NULL)

ads(id uuid PK, code UNIQUE, title, media_type varchar(8) CHECK video|image|text,
    body_text text NULL,        -- media_type=text zorunlu
    media_url text NULL,        -- video/image zorunlu (https dosya URL'i)
    content text NULL,          -- text için gövde; image için alt metin
    target_url text NULL,       -- affiliate URL, https zorunlu (boş olabilir)
    watch_seconds int CHECK(>0),
    watch_reward bigint CHECK(>=0),   -- jeton (TOKEN, minor)
    click_reward bigint CHECK(>=0),   -- jeton (TOKEN, minor)
    starts_at, ends_at NULL, active bool, timestamps)

ads_clicks(id uuid PK, ad_id uuid, user_id uuid NULL, kind varchar(8) CHECK click|view_redirect,
           reward_date date NULL, ip_hash varchar(64) NULL, created_at)
  UNIQUE (user_id, ad_id, reward_date) WHERE kind = click AND reward_date IS NOT NULL

ad_view_sessions(id uuid PK, ad_id uuid, user_id uuid,
                 required_seconds int CHECK(>0),
                 status varchar(10) CHECK started|rewarded,
                 server_started_at timestamptz, expires_at timestamptz,
                 reward_minor bigint CHECK(>=0), reward_date date,
                 entry_id uuid NULL, created_at)
  UNIQUE (user_id, ad_id, reward_date)

reward_settings(id int PK DEFAULT 1,              -- tekil satır (id=1)
    signup_grant bigint CHECK(>=0),               -- default 10 (TOKEN)
    ad_watch_reward bigint CHECK(>=0),            -- default 1
    daily_reward_cap bigint CHECK(>=0),           -- default 3
    monthly_reward_cap bigint CHECK(>=0),         -- default 10
    click_reward_enabled bool DEFAULT true,
    updated_at, updated_by uuid)

refunds(id uuid PK, payment_id, amount_minor CHECK(>0), provider_ref, status, reason)
```

`products` için ek kural (rev 1.1): `kind` değerleri artık
`token_pack | subscription | regular` ve `meta jsonb` kolonu vardır;
`token_pack` → `meta = {"tokens": 50}`, `subscription` →
`meta = {"entitlement": "premium.vip"}` şartı servis tarafından doğrulanır.

`app_id` kolonu **yoktur**: her uygulama kendi veritabanında çalışır. Uygulamaya
özel veri `products.grants` ve `entitlements.code` içinde yaşar.

### 3.3 Bakiye güncelleme — yarışsız

Tek koşullu UPDATE; oku-sonra-yaz yok:

```sql
UPDATE wallet_accounts
   SET balance_minor = balance_minor + $delta, updated_at = now()
 WHERE id = $account_id AND balance_minor + $delta >= 0
RETURNING balance_minor;
```

0 satır → yetersiz bakiye (`402`). 1 satır → aynı transaction'da `wallet_entries`
satırı `balance_after_minor` ile yazılır. `CHECK (>=0)` ikinci güvenlik ağıdır.

**Invariant:** `SUM(wallet_entries.delta_minor) = wallet_accounts.balance_minor`.
`corectl doctor` bunu doğrular.

### 3.4 Sebep kodları

| Kod | Tetikleyen | Yön | Kullanıcı endpoint'i |
|---|---|---|---|
| `signup_grant` | sistem (cüzdan ilk açılış) | + | `GET /wallet` ilk çağrıda otomatik işler |
| `daily_bonus` | sistem (miktarı sunucu belirler) | + | `POST /wallet/daily-bonus` |
| `ad_watch_reward` | sistem (imzalı izleme oturumu, süre sunucu saatiyle doğrulanır) | + | `POST /ads/:id/view` + `claim` |
| `ad_click_reward` | sistem (platform redirect'inden ölçülen tıklama) | + | `GET /ads/:id/click` (redirect'in kendisi) |
| `purchase` | sistem (ödeme onayı / token_pack fulfillment) | + | yok |
| `refund` | sistem | + | yok |
| `admin_credit` / `admin_debit` | admin (sebep zorunlu) | ± | yok |
| `spend_feature` / `spend_ai` | modül | − | yok |
| `expire` | sistem (job) | − | yok |

**Kritik (rev 1.1 ile güncellendi):** Kullanıcıya açık "miktar
göndererek jeton kazan" endpoint'i **yoktur**. Reklam ödülünde miktar
(`watch_reward` / `click_reward`), süre (`watch_seconds`) ve limit
(`daily_reward_cap` / `monthly_reward_cap`) tamamen sunucudan gelir; istek
gövdesindeki herhangi bir tutar alanı yoksayılır/reddedilir. Harcama da
serbest sebep kabul etmez; yalnızca `Wallet.Debit(...)` ile modül içinden
yapılır. Tek kullanıcı-tetikli istisnalar: `daily_bonus` ve reklam izleme
oturumu — ikisinde de miktar sunucuda tanımlıdır ve idempotency anahtarı
kullanıcı+gün+nesne bazlıdır:
`daily_bonus:<userID>:<YYYY-MM-DD>`,
`ad_watch:<sessionID>`,
`ad_click:<userID>:<adID>:<YYYY-MM-DD>`,
`signup_grant:<userID>`.

### 3.5 Sipariş akışı — tek durum makinesi

**Yol A — jetonla (sağlayıcısız):** ürün `currency == TOKEN` → transaction içinde
`Debit` + `order.status = fulfilled` + entitlement. Yetersiz bakiye → `402`,
sipariş `failed` olarak kaydedilir.

**Yol B — fiat (sağlayıcılı):** `pending` + referans kodu → `CreateCheckout` →
kullanıcı öder → imzalı olay veya admin onayı → `fulfilled` + entitlement.

```
created → pending → paid → fulfilled
                  ↘ failed
        ↘ expired
fulfilled → refunded
```

Geçişler yalnızca servis içinde ve `UPDATE ... WHERE status = $beklenen` ile.
`fulfilled` bir kez olur; entitlement `(order_id)` bazında idempotenttir.

### 3.6 Ödeme adaptör arayüzü

```go
type PaymentProvider interface {
    Name() string
    Capabilities() ProviderCapabilities
    CreateCheckout(ctx context.Context, in CheckoutInput) (CheckoutResult, error)
    ParseWebhook(r *http.Request) (ProviderEvent, error)
    Refund(ctx context.Context, in RefundInput) (RefundResult, error)
}
```

| Adaptör | L2'de |
|---|---|
| `token` | Var — cüzdandan düşer, sağlayıcı yok |
| `manual` | Var — referans + banka talimatı, admin onayı |
| `test` | Var — anında `paid`, yalnızca `APP_ENV != production` |
| `stripe` | **Sonra** — ayrı adaptör |
| `paytr` | **Sonra** — ayrı adaptör |

Yeni adaptör = bir paket + arayüz + kayıt satırı. Cüzdan, sipariş, entitlement
ve durum makinesi **değişmez**. Bu bir kabul kriteriyle kanıtlanır.

### 3.7 Webhook ve idempotency

- Route: `POST /api/v1/payments/webhook/{provider}` — auth'tan muaf, kendi imza
  doğrulaması, ayrı rate limit.
- Akış: doğrula → `payment_events` INSERT (`(provider, event_id)` unique) →
  çakışırsa 200 dön ve çık → transaction: `payments` yaz → `orders` koşullu
  ilerlet → entitlement ver.
- Geçersiz imza → `401`, olay kaydedilmez.
- Sağlayıcıya her durumda 200 dönülür (tekrar denemeyi durdurmak için).

### 3.8 Güvenlik

- Tutar ve para birimi **asla** istekten alınmaz; `product_id` → sunucu fiyatı.
- `idempotency_key` sipariş oluşturmada **zorunlu**; tekrar gelirse mevcut sipariş döner.
- Kullanıcı yalnızca kendi siparişini/cüzdanını görür; başkasınınki **404**.
- Admin endpoint'leri `RequireRole("admin")` arkasında.
- Log'larda kart verisi, sağlayıcı sırrı, tam e-posta yok.

### 3.9 Zamanlanmış işler

| İş | Sıklık | Ne yapar |
|---|---|---|
| Süresi geçen siparişler | 1 dk | `pending` + `expires_at < now()` → `expired` |
| Biten abonelikler | 1 saat | `ends_at < now()` → pasif (silmez) |
| Ledger denetimi | günlük | `SUM(delta) != balance` hesapları raporlar |

Enjekte `Clock` ile test edilir; çok instance'ta `pg_advisory_lock`.

### 3.11 Ödüllü reklam — jeton kazanma (rev 1.1)

**Akış: izleme + geri sayım**

1. Kullanıcı `GET /ads/token` → sunucu günlük/aylık cap kontrolü yapar,
   uygunsa kullanıcı bazlı nöbet sırasına göre jetonlu, aktif bir reklam
   seçer (`AD_NOT_AVAILABLE` değilse).
2. `POST /ads/:id/view` → `ad_view_sessions` satırı açılır:
   `required_seconds = ads.watch_seconds`, `server_started_at = now()`,
   `expires_at = now() + (2 × watch_seconds, en çok 5 dk)` — istemci saatine
   hiç güvenilmez.
3. İstemci geri sayımı yerel UI'da gösterir; süre bitince
   `POST /ads/view/:sessionID/claim` → sunucu kontrol eder:
   `now() ≥ server_started_at + required_seconds`, oturum `started`,
   `now() < expires_at`. Aksi her durumda `REWARD_TOO_EARLY` (409);
   oturum ile oynanamaz, erken claim ödül vermez.
4. Limitler geçilebilir mi (`daily_reward_cap`, `monthly_reward_cap`,
   takvim ayı bazlı) → geçilemezse `REWARD_LIMIT_REACHED` (429).
5. Ödül: `Wallet.Credit(reason=ad_watch_reward)` aynı transaction'da;
   oturum `rewarded` (tekrar claim = aynı başarılı sonuç döner, yeni ödül
   yazılmaz). Idempotency: `ad_watch:<sessionID>`.

**Akış: tıklama (affiliate)**

1. `GET /ads/:id/click` (auth gerekli) → `ads_clicks` kaydı (gün bazlı
   unique) → tıklama ödülü (`click_reward`) açık ve limit uygunsa
   `ad_click_reward` ledger hareketi → sonra `302 → ads.target_url`.
2. `target_url` yok ise redirect yok (yalnız stat/ödül). Affiliate URL
   https şeması zorunlu; http ve javascript: reddedilir.
3. Tıklama ödülü de aynı günlük/aylık havuzdan düşer → toplam kazanma
   limiti izleme + tıklama toplamına uygulanır.

**Limit ayarları (`reward_settings`):** admin `PUT /admin/reward-settings`
ile değiştirilebilir; değişiklik anında yeni ödül işlemlerine uygulanır,
geçmiş geriye dönük etkilemez. Değerler admin endpoint'i dışından
değiştirilemez (config'te sadece ilk seed).

### 3.12 Jeton paketleri ve abonelik (rev 1.1)

- **`token_pack`**: products `currency=TRY, amount_minor=satış fiyatı`,
  `meta.tokens ∈ {10, 50, 100, ...}`. Fulfillment anında
  `Wallet.Credit(reason=purchase, TOKEN, meta.tokens)`. Sipariş akışı
  §3.5 Yol B ile birebir aynıdır: `manual` sağlayıcı (banka talimatı +
  admin onayı) ile uçtan uca kanıtlanır; gerçek sağlayıcı sonra adaptör
  olur.
- **`subscription`**: products `kind=subscription`,
  `meta.entitlement = <entitlement code>`, `interval` (ay). Fulfillment
  anında entitlement `starts_at=paid_at`, `ends_at = +interval` verilir.
  Otomatik yenileme **yoktur**; abonelik ya kullanıcı yeniden satın alır
  ya admin uzatılır (recurring charge sağlayıcı gerektirdiğinden dışarıda).
- **Ücretsiz üyelik**: kayıt identity'in işi ve ücretsizdir; ekonomi modülü
  ücretli bilet istemez. Hoş geldin jetonu: kullanıcının cüzdanı **ilk
  erişimde** (`GET /wallet`) açılır ve `signup_grant` (default 10 TOKEN)
  tek kez, `idempotency_key=signup_grant:<userID>` ile kredilenir.
  Cüzdanı olan her kullanıcının tam bir `signup_grant` veya `admin_credit`
  hareketi vardır; bunu `corectl doctor` invariant olarak doğrular.
