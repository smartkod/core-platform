> (config'ten) · prompt engine L3'te, **context engine uygulamada**.

## 1. Bu seviye ne ekler

```bash
corectl new eduscope --level=L3
# veya kota jetonla ödenecekse (L2 gerekir):
corectl new eduscope --level=L3 --with-economy
```

| Modül | Ne getirir |
|---|---|
| `ai` | Sağlayıcı arayüzü, kota, cache, kullanım/maliyet kaydı, prompt şablonları |

Şema: `ai_usage`, `ai_cache`, `ai_prompts`, `ai_quotas`.
Arayüz: `contract/ai` → `AIProvider`.

Bir uygulama L3 ile: sağlayıcı kesintisinde ayakta kalan, kullanıcı bazında
kotalı ve maliyeti izlenebilir AI çağrıları yapar — sağlayıcı değiştirmek
çekirdeği değiştirmez.

2. Bir uygulama geliştiricisi olarak, kota kontrolünü çekirdeğe bırakmak
   istiyorum, böylece her çağrıda sayacı elle yönetmem.

3. Bir uygulama geliştiricisi olarak, aynı prompt'un ikinci kez sağlayıcıya
   gitmemesini istiyorum, böylece maliyet düşer ve yanıt hızlanır.

4. Bir uygulama geliştiricisi olarak, prompt şablonlarını sürümleyebilmek
   istiyorum, böylece bir değişikliğin hangi sürümde olduğunu bilirim.

5. Bir uygulama geliştiricisi olarak, L3'ü eklerken `main.go`'ya tek satır
   yazmak istiyorum.

6. Bir uygulama geliştiricisi olarak, kendi sohbet geçmişimi kendi şemamda
   tutabilmek istiyorum, böylece domain modelim çekirdeğe sızmaz.

### 2.2 Operatör

7. Bir operatör olarak, bir kullanıcının AI maliyetini görebilmek istiyorum,
   böylece sürpriz fatura olmaz.

8. Bir operatör olarak, sağlayıcı kesintisinde uygulamanın ayakta kalmasını

### 2.3 Son kullanıcı

11. Bir kullanıcı olarak, günlük kotamı aştığımda net bir mesaj görmek

### 2.4 Mimar / güvenlik

    olmasını istiyorum.

14. Bir mimar olarak, sağlayıcı hatalarının cache'lenmemesini istiyorum, böylece

15. Bir mimar olarak, log'larda prompt ve kişisel verinin maskelenmesini

    istiyorum, böylece template injection imkânsız olur.

17. Bir mimar olarak, L3'ün L2 olmadan çalışabilmesini istiyorum, böylece AI
    kullanan ama para dönmeyen uygulama cüzdan taşımaz.

## 3. Uygulama Kararları

### 3.1 Sağlayıcı arayüzü

```go
type AIProvider interface {
    Name() string
    Capabilities() ProviderCapabilities // chat, embed, count_tokens
    Chat(ctx context.Context, in ChatInput) (ChatResult, error)
    CountTokens(ctx context.Context, text string) (int, error)
}
```

- **Streaming V1'de yok.** `ChatStream` arayüzde **tanımlanmaz**; sonradan
  ayrı metot olarak eklenir ve mevcut kodu bozmaz.
- `ChatInput`: model, mesajlar, `MaxTokens`, `Temperature`, `Stop`, `UserID`.
- `ChatResult`: içerik, `Usage{PromptTokens, CompletionTokens}`, sağlayıcı adı,
  model, `LatencyMS`.

### 3.2 Adaptörler

| Adaptör | L3'te |
|---|---|
| `test` | Var — deterministik yanıt; E2E ve cache testleri için |
| `openai` | **Sonra** — ayrı adaptör |
| `anthropic` | **Sonra** |
| `gemini` | **Sonra** |

Yeni sağlayıcı = bir paket + arayüz implementasyonu + config kaydı. Kota, cache,
maliyet ve dayanıklılık kodu **değişmez**. Bir kabul kriteriyle kanıtlanır.

`test` adaptörü üretimde **kaydedilmez** (config drift fail-fast).

### 3.3 Şema

```sql
ai_usage(id uuid PK, user_id uuid, provider varchar(20), model varchar(60),
         prompt_tokens int, completion_tokens int, cost_micro bigint,
         prompt_hash char(64), cached bool, status varchar(20),
         latency_ms int, created_at timestamptz)
  INDEX (user_id, created_at DESC)

ai_cache(id uuid PK, prompt_hash char(64), model varchar(60), provider varchar(20),
         response jsonb, tokens int, expires_at timestamptz, created_at)
  UNIQUE (prompt_hash, model, provider)

ai_prompts(id uuid PK, code varchar(80), version int, template text,
           variables jsonb, owner varchar(80), active bool, created_at)
  UNIQUE (code, version)

ai_quotas(id uuid PK, user_id uuid, day date, requests int, tokens int)
  UNIQUE (user_id, day)
```

`cost_micro` = mikro-dolar (`int64`). `float` yasak.
**Sohbet geçmişi/context tablosu yok**: context engine uygulamaya aittir.

### 3.4 Kota — iki mod, config'ten

```yaml
ai:
  quota:
    mode: counter          # counter | wallet
    counter:
      requests_per_day: 100
      tokens_per_day: 100000
    wallet:
      currency: TOKEN
      tokens_per_credit: 1000
```

| Mod | Davranış | L2 gerekli |
|---|---|---|
| `counter` | `ai_quotas` üzerinden günlük sayaç | Hayır |
| `wallet` | çağrı başına `Wallet.Debit(spend_ai)` | **Evet** |

- `wallet` modu seçilip L2 derlemede yoksa bootstrap **fail-fast** eder
  ("quota mode wallet requires the economy module").
- Aşımda `429 RATE_LIMITED` (kota) — yetersiz bakiye ayrı: `402`.
- Sayaç artırımı çağrı **öncesi** yapılır (rezervasyon), hata durumunda geri
  alınır; böylece eşzamanlı istekler limiti aşamaz.

### 3.5 Cache

- Anahtar: `sha256(normalized_prompt + model + provider)`.
- Hit → sağlayıcı çağrılmaz; `ai_usage.cached = true`.
- **Hata asla cache'lenmez.**
- TTL config'ten (`ai.cache.ttl`, varsayılan 24h).
- `temperature > 0` ise varsayılan olarak cache'lenmez (opsiyonel `force` bayrağı).
- Cache yalnızca `cache.enabled: true` iken çalışır.

### 3.6 Dayanıklılık

| Mekanizma | Kural |
|---|---|
| Timeout | `ai.request_timeout` (varsayılan 30s) |
| Retry | Yalnızca 5xx ve timeout; üstel geri çekilme + jitter; en fazla 2 |
| Circuit breaker | 5 ardışık hata → 30s açık; açıkken **503** |
| Fallback | Sağlayıcı listesi config'ten; birincil düşerse ikincil denenir (varsa) |

Sağlayıcı kesintisinde uygulama **ayakta kalır**; istek 503 alır, süreç düşmez.

### 3.7 Maliyet izleme

- Sağlayıcı fiyat tablosu config'ten (`ai.pricing.<provider>.<model>`).
- Her çağrı `ai_usage` satırı yazar: token, maliyet, gecikme, cache durumu.
- `GET /api/v1/admin/ai/usage?from=&to=&user_id=` ile raporlanır.
- Kullanıcı bazında toplam maliyet görülebilir.

### 3.8 Prompt engine

- `ai_prompts`: `code` + `version`, `text/template` **değil** `strings` tabanlı
  güvenli yerleştirme; keyfi fonksiyon yok.
- Değişkenler `variables jsonb` ile beyan edilir; eksik değişken → hata
  (`missingkey=error` eşleniği).
- Şablon sahibi (`owner`) ve sürümü kaydedilir; `active` bir sürüm işaretlenir.
- `GET /ai/prompts/:code` aktif sürümü döner.

**Context engine kapsam dışı:** oturum, mesaj geçmişi, token bütçesi ve
özetleme uygulamanın kendi şemasında yaşar. Çekirdek yalnızca `Chat` çağrısını
yapar.

### 3.9 Güvenlik

- Log'larda prompt gövdesi **maskelenir**; yalnızca `prompt_hash` ve uzunluk.
- `user_id` her çağrıda kaydedilir; anonim çağrı yok.
- Sağlayıcı anahtarı yalnızca env'den (`AI_API_KEY`); repoda yok.
- İstemciden `model` ve `max_tokens` sınırlanır (allow-list).
- Prompt injection: sistem mesajı ile kullanıcı mesajı ayrı alanlarda tutulur;
  çekirdek bunları birleştirmez.

### 3.10 API

```
POST   /api/v1/ai/chat              kota + rate limit
GET    /api/v1/ai/providers         aktif sağlayıcılar (yeteneksel)
GET    /api/v1/ai/quota             kullanıcının kalan kotası
GET    /api/v1/ai/prompts/:code     aktif prompt şablonu

GET    /api/v1/admin/ai/usage       kullanım ve maliyet raporu
GET    /api/v1/admin/ai/cache/stats cache etkinliği
```

Ek hata kodları: `RATE_LIMITED` (429, kota), `PROVIDER_ERROR` (502),
`NOT_IMPLEMENTED` (501, adaptör yok).

## 4. Test Kararları

Gerçek PostgreSQL. Sağlayıcı çağrıları `test` adaptörü veya `httptest` ile
deterministik; gerçek ağ çağrısı testlerde **yok**.

**Kota**
1. `counter` modu: günlük limit aşıldığında 429; ertesi gün sıfırlanır.
2. Eşzamanlı 50 istek (`-race`) limiti aşamaz (rezervasyon geri alınır).
3. `wallet` modu: çağrı jeton düşer; yetersizse 402 ve sağlayıcı çağrılmaz.
4. `wallet` modu seçili ama L2 derlemede yoksa bootstrap **başlamaz**.

**Cache**
5. Aynı prompt iki kez → sağlayıcı **bir** kez çağrılır; ikincisi `cached=true`.
6. Sağlayıcı hattası cache'lenmez; ikinci istek yeniden dener.
7. TTL dolduğunda yeniden çağrılır.
8. `temperature > 0` cache'lenmez (varsayılan).

**Dayanıklılık**
9. Sağlayıcı timeout → 503, süreç ayakta.
10. 5 ardışık hata → circuit açılır; sonraki istek sağlayıcıya gitmeden 503.
11. Retry yalnızca 5xx ve timeout'ta; 4xx'te retry yok.

**Maliyet ve güvenlik**
12. Her çağrı `ai_usage` satırı yazar; `cost_micro` doğru hesaplanır.
13. Log'da prompt gövdesi yok (log tarama testi).
14. İstemciden gelen allow-list dışı `model` reddedilir.
15. Prompt şablonunda eksik değişken hata verir; keyfi fonksiyon çalışmaz.

**Genişletilebilirlik**
16. **`stub` adaptörü yalnızca arayüz + kayıt satırıyla çalışır**; kota/cache/
    maliyet kodu değişmez.
17. `test` adaptörü üretimde kaydedilmez.

## 5. Kabul Kriterleri

L3 tamam = L0 ∧ L1 ∧ aşağıdakiler (L2 yalnızca `wallet` kota modunda).

1. `corectl new demo --level=L3` üretilen proje elle düzenleme olmadan derlenir.
2. `docker compose up` ile ayağa kalkar; `/readyz` 200.
3. Sağlayıcı timeout'unda istek 503 alır, süreç ayakta kalır.
4. Kota aşıldığında 429; eşzamanlı istekler limiti aşamaz.
5. Aynı prompt ikinci kez sağlayıcıya gitmez; `cached=true` işaretlenir.
6. Sağlayıcı hatası cache'lenmez.
7. Circuit breaker açıldığında sağlayıcıya istek gitmez.
8. Her çağrı için `ai_usage` kaydı ve `cost_micro` doğru.
9. Kullanıcı bazında toplam maliyet raporlanabilir.
10. Log'larda prompt gövdesi/PII yok (log tarama testi).
11. Allow-list dışı `model` reddedilir.
12. `wallet` modu L2 olmadan bootstrap **başlamaz** (fail-fast kanıtı).
13. **Yeni sağlayıcı testi geçer**: yalnızca adaptör + kayıt satırı.
14. `test` adaptörü `APP_ENV=production` iken kaydedilmez.
15. `go test -race ./...` yeşil; coverage ≥ %50.

## 6. Kapsam Dışı

- **Streaming (SSE)** — arayüzde bile yok; sonradan ayrı metot.
- **Gerçek sağlayıcı adaptörleri** (OpenAI, Anthropic, Gemini) — sonraki sürüm.
- **Context / session engine** — oturum, mesaj geçmişi, özetleme uygulamada.
- Embedding üretimi ve vektör arama (ayrı bir yetenek; V1'de yok).
- Fine-tuning, tool/function calling, agent framework.
- Görsel/ses üretimi.
- Sağlayıcı faturalarının otomatik mutabakatı.

## 7. Notlar

### 7.1 Kararlar

| # | Karar | Gerekçe |
|---|---|---|
| A1 | `test` adaptörü + arayüz; gerçek sağlayıcı sonra | L2'nin `manual`+`test` deseninin eşleniği |
| A2 | Streaming V1'de yok | SSE altyapısı ve testi ciddi iş; sonradan eklenir |
| A3 | Kota `counter` veya `wallet` | AI kullanan ama para dönmeyen uygulama L2 taşımaz |
| A4 | Prompt engine L3'te, context uygulamada | Şablon genel; oturum şeması domain'e özgü |
| A5 | Cache anahtarı prompt+model+provider | Sağlayıcıya geçişte karışma olmaz |
| A6 | Hata cache'lenmez | Geçici hata kalıcılaşmasın |
| A7 | Maliyet `int64` mikro-dolar | `float` yasak |
| A8 | Circuit breaker 5 hata / 30s | Tek sağlayıcı kesintisi tüm uygulamayı düşürmez |

### 7.2 Açık sorular

| # | Soru | Önerilen varsayılan |
|---|---|---|
| S1 | Kota limitleri uygulamaya özel mi? | Config'ten; varsayılan 100 istek/gün |
| S2 | `wallet` modunda dönüşüm oranı | Config'ten (`tokens_per_credit`) |
| S3 | Prompt saklama süresi | Süresiz; uygulama temizler |
| S4 | Fallback sağlayıcı zinciri | V1'de tek sağlayıcı; alan hazır |

### 7.3 L2 ile ilişki

L3, L2 olmadan tam çalışır (`counter` kota). Kota jetonla ödenecekse
`--with-economy` ile L2 birlikte seçilir; o zaman `Wallet.Debit(spend_ai)`
kullanılır. Bu, tek yönlü ve opsiyonel bir bağımlılıktır.
