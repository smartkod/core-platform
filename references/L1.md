| | |
|---|---|
| **Sürüm** | 1.0 |
| **Tarih** | 2026-11-01 |
| **Seviye** | L1 |
| **Ön koşul** | L0 (`L0.md`) |
| **Üst belge** | `PRD.md` |
| **Durum** | **L1 tamamlandı** — `identity` ✅ `files` ✅ `notifications` ✅ · `search` çekirdek dışı |

> **Kapsam kuralı:** Yalnızca L1'in ekledikleri. L0 metni kopyalanmaz.
>
> **Kümülatif okuma:** L1 tamam = (L0 kriterleri) ∧ (bu belgedeki kriterler).

> **Kapsam kararı (2026-11-01):** L1 = kimlik + dosya + bildirim.
> `search` L1'de **değil**: aranan alanlar ve skorlama her uygulamada farklı
> olduğu için çekirdek dışında `helper/search` yardımcı paketi olarak verilir.

## 1. Bu seviye ne ekler

```bash
corectl new fitscope --level=L1
corectl new xscope   --level=L1 --only=identity,files
```

| Modül | Ne getirir |
|---|---|
| `identity` | Kullanıcı, kayıt/giriş, JWT, refresh rotation, RBAC, `/me` |
| `files` | `Storage` arayüzü, yükleme/indirme, imzalı URL, sahiplik |
| `notifications` | Outbox, şablon, tercih, e-posta adaptörü |

Şema: `users`, `refresh_tokens`, `email_verifications`, `password_resets`,
`files`, `notifications`, `notification_preferences`.
Arayüz: `contract/core` → `Identity`, `Storage`, `Notifications`.

Bir uygulama L1 ile: kullanıcı kaydı ve oturumu, dosya yükleme ve bildirim
gönderme hazır gelir. Kendi iş mantığına odaklanır.

## 3. Uygulama Kararları

### 3.1 `identity` — kimlik ve oturum

**Şema**

```sql
users(id uuid PK, email citext UNIQUE, password_hash, name, locale,
      avatar_url, role, status, email_verified_at, last_login_at,
      token_version int, created_at, updated_at, deleted_at)

refresh_tokens(id uuid PK, user_id, token_hash, family_id, device, ip,
               expires_at, revoked_at, replaced_by)
  INDEX (user_id), INDEX (token_hash)

email_verifications(id, user_id, token_hash, expires_at, used_at)
password_resets(id, user_id, token_hash, expires_at, used_at)
```

- `users` ve `auth` **tek model** — ayrı `users` modülü yok.
- Şifre: Argon2id (fallback bcrypt cost 12). Politika: en az 10 karakter,
  uzunluk üst sınırı 72 (bcrypt uyumu için).
- **`citext`** e-posta tekilliği için; büyük/küçük harf duyarsız.

**Token modeli — iki taşıma, tek servis**

| İstemci | Taşıma | CSRF |
|---|---|---|
| Mobil / CLI / 3. parti | `Authorization: Bearer` | Yok |
| Web tarayıcı | `access` + `refresh` HttpOnly cookie | Double-submit |

- İkisi aynı anda gelirse **Bearer kazanır** (karışık mod saldırısı önlenir).
- Access 15 dk; refresh 7 gün (mobil) / 30 gün (web "beni hatırla").
- Access ve refresh **ayrı secret**, ayrı `aud`.
- Refresh token'lar DB'de **hash'lenmiş**.
- **Rotation zorunlu**: her refresh eski token'ı iptal eder. Yeniden kullanım
  tespitinde `token_version++` ile **tüm aile** iptal edilir.
- Claims: `sub`, `sid`, `jti`, `role`, `scopes`, `ver`, `iat`, `exp`, `iss`, `aud`.
- Cookie: `HttpOnly`, `Secure` (prod), `SameSite=Lax`, `Path=/api/v1/auth`.
- Logout: cookie temizlenir + aile iptal edilir.
- Şifre sıfırlama ve e-posta doğrulama **tüm oturumları** iptal eder.

**Endpoint'ler**

```
POST /api/v1/auth/register       POST /api/v1/auth/login
POST /api/v1/auth/refresh        POST /api/v1/auth/logout
POST /api/v1/auth/forgot-password
POST /api/v1/auth/reset-password
POST /api/v1/auth/verify-email
GET  /api/v1/me                  PATCH /api/v1/me     DELETE /api/v1/me
GET  /api/v1/admin/users         DELETE /api/v1/admin/users/:id
```

**RBAC:** `RequireRole("admin")` middleware; rol `users.role` alanında.
Tüm admin endpoint'leri korumalı. Hiçbir handler sabit kullanıcı ID'si kullanmaz;
kimlik `context`'ten gelir.

**Rate limit:** login/register/refresh için IP **ve** e-posta kombinasyonu
(ayrı sayaçlar). Aşımda `429`.

**E-posta:** `Mailer` arayüzü (SMTP / Resend); geliştirmede MailHog.
Doğrulama ve sıfırlama token'ları hash'lenmiş saklanır, tek kullanımlık.

### 3.2 `files`

- `Storage` arayüzü: `Put`, `Get`, `Delete`, `SignedURL`.
- İki implementasyon: `local` (disk) ve `s3` (uyumlu). Config'ten seçilir.
- `baseURL` config'ten; kodda sabit URL yok.
- **SVG yasak.** İçerik tipi `mimetype` ile doğrulanır, uzantıya güvenilmez.
- Boyut limiti config'ten; aşımda `413`.
- Sahiplik: her dosya `user_id` taşır. Başkasının dosyası **404** (varlık sızdırmaz).
- İndirme imzalı URL ile; URL süreli.
- Depolama yolu tahmin edilemez (UUID tabanlı).

```
POST   /api/v1/files            (multipart)
GET    /api/v1/files            kendi dosyaları
GET    /api/v1/files/:id        metadata + imzalı URL
DELETE /api/v1/files/:id
```

### 3.3 `notifications`

- **Outbox deseni:** bildirim önce DB'ye yazılır (`pending`), gönderim ayrı
  adımda yapılır. Böylece e-posta servisi düşse bile bildirim kaybolmaz.
- Retry: üstel geri çekilme, en fazla 5 deneme; sonra `failed`.
- `IsSent` alanı gerçekten güncellenir (eski kodda güncellenmiyordu).
- Şablonlar `embed.FS` içinde; `en` + `tr`.
- Tercih kontrolü: kullanıcı bir kanalı kapatırsa gönderim atlanır (kayıt yine
  `skipped` olarak tutulur).
- Kanal adaptörleri: `email` (SMTP/Resend). Push V1'de yok.

```
GET  /api/v1/notifications                 GET  /api/v1/notifications/unread-count
POST /api/v1/notifications/:id/read        POST /api/v1/notifications/read-all
GET  /api/v1/notifications/preferences     PUT  /api/v1/notifications/preferences
```

### 3.4 `helper/search` — çekirdekte değil

- `pg_trgm` + GIN index kuran ve `ILIKE` yerine benzerlik skorlayan ~40 satırlık
  yardımcı paket, `contract` dışında.
- Aranacak alanlar, skorlama ve filtreler **uygulamaya** ait.
- `offset` gerçekten uygulanır; bozuk girdi panic üretmez; SQL injection yok.
- Bu paket L1 derlemesine **dahil değildir**; isteyen uygulama import eder.

### 3.5 Config eklemeleri

```yaml
identity:
  jwt:
    access_ttl: 15m
    refresh_ttl: 168h        # 7 gün
    refresh_ttl_remember: 720h
  password:
    min_length: 10
  mailer:
    provider: smtp           # smtp | resend | noop

files:
  driver: local              # local | s3
  base_url: http://localhost:8080
  max_size: 10MB
  allowed_types: [image/png, image/jpeg, application/pdf]
  s3: { bucket, region, endpoint }

notifications:
  worker_interval: 10s
  max_attempts: 5
```

Üretimde fail-fast: `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` boşsa **başlamaz**.

### 3.6 `corectl` davranışı

- `--only=identity,files` → yalnızca o modüllerin kodu, migration'ı, route'u,
  config bloğu ve `.env.example` satırları üretilir.
- Bağımlılık otomatik eklenir: `files` → `identity` (istenmese bile eklenir ve
  **raporlanır**).
- `--only` ile istenmeyen modülün tablosu **oluşmaz**.

## 4. Test Kararları

Gerçek PostgreSQL. `-race` zorunlu (refresh rotation yarışı).

**Kimlik**
1. register → login → korumalı `/me` → refresh → logout uçtan uca.
2. Logout sonrası eski refresh token reddedilir.
3. Çalınmış refresh token yeniden kullanılırsa **tüm aile** iptal; eski access
   token bir sonraki doğrulamada geçersiz.
4. Bearer + cookie aynı anda → Bearer kazanır; Bearer'da CSRF istenmez,
   cookie modunda istenir. Access cookie'si taşımayan (anonim) POST istekleri
   (login/register gibi) CSRF'den muaftır: çapraz-site form gönderisinin
   faydalanabileceği bir çerez kimliği yoktur.
5. Yetkisiz → 401; yanlış rol → 403; başkasının kaynağı → 404.
6. Şifre sıfırlama tüm oturumları iptal eder.
7. Login rate limit: IP + e-posta kombinasyonu; 5 hatalı denemeden sonra 429.
8. E-posta doğrulama token'ı tek kullanımlık.
9. Zayıf şifre reddedilir; 72 karakterden uzun şifre reddedilir.

**Dosya**
10. Başkasının dosyası → 404 (IDOR).
11. SVG yüklemesi reddedilir.
12. Boyut aşımı → 413.
13. Uzantı `.png` ama içerik farklı → reddedilir.
14. İmzalı URL süresi geçince 403.

**Bildirim**
15. Başarısız gönderim yeniden denenir; `attempts` artar.
16. 5 denemeden sonra `failed`; `IsSent` doğru.
17. Tercih kapalıysa gönderim atlanır (`skipped`).
18. Outbox satırı olmadan gönderim yapılmaz.

**İzolasyon**
19. `--only=identity` ile üretilen projede `files` route'u yok, tablosu yok.
20. L1-only derleme `mod/economy` ve `mod/ai` import etmiyor (depguard kanıtı).

İnceleme notları:

- **`http.TimeoutHandler` kaldırıldı.** Echo'nun Timeout middleware'i yanıtı
  bellekte tamponluyordu; 10 MB'lık bir indirme ilk bayt gitmeden RAM'de
  birikirdi ve multipart gövdeyle çakışıp panic üretiyordu. Yerine yalnızca
  context iptali yapan bir middleware kondu — handler yanıtın sahibi kalır,
  streaming çalışır.
- **Modüller arası servisler Start'tan SONRA bağlanıyor.** `wireProviders`
  önceden çağrıldığında `Identity()` nil dönüyor, nil pointer bir interface'e
  sarılınca `!= nil` oluyor ve ilk istekte panic veriyordu. Artık sağlayıcılar
  Start sonrası çözülüyor ve nil döndürenler atlanıyor.
- **Docker imajı `/app/data` dizinini oluşturup `10001` kullanıcısına veriyor.**
  Aksi halde `files` modülü açılışta "permission denied" ile ölüyordu.
  `uploads` adlı bir volume eklendi, böylece yeniden build dosyaları silmiyor.

Kalan: `notifications`.

İnceleme notları:

- **Outbox deseni.** Mesaj önce DB'ye yazılır, worker sonra gönderir. Posta
  sunucusu çökse mesaj kaybolmaz, gecikir. Gönderilen konu ve gövde de saklanır:
  şablon sonradan değişse bile retry orijinali gönderir.
- **`FOR UPDATE SKIP LOCKED`.** Birden fazla worker aynı satırı göndermez. Bu
  olmadan iki instance her e-postayı iki kez atardı.
- **Tercih yokluğu = varsayılan açık.** Yeni kullanıcı ayar sayfasına gitmeden
  transactional mail alır.
- **İki şablon motoru.** `text/template` düz metin için (kaçış yok),
  `html/template` HTML için (kaçış şart). HTML gövdeyi `text/template` ile
  render etmek, kullanıcı verisinin mail'e markup sokmasına izin verirdi.
- **`missingkey=error`.** Şablon değişkeninde yazım hatası `<no value>` olarak
  müşteriye gitmez, hata verir.
- **Posta taşıması arayüz arkasında.** `platform/mailer` üç sürücü sunar: SMTP,
  log'a yazan (geliştirmede sıfır kurulum), ve hiçbir şey yapmayan. V1'de
  `mailer: nil` → mesaj kuyruğa girer, gönderilmez.
